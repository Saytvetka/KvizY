# Каркас BiletY: как устроено и что где менять

Это карта приложения. Когда захочешь что-то поменять — найди здесь нужный пункт и скажи Claude: «поменяй в `файл` вот это».

BiletY лежит в папке `bilety/` репозитория KvizY и устроен так же, как KvizY (тот же сервер, база, вход, ИИ-адаптер, деплой), но это отдельное приложение со своим адресом, своей базой и своим паролем.

---

## 1. Идея и принципы

**Что делает:** загружаешь от 1 до 5 файлов (PDF, Word, PowerPoint, фото конспекта, текст, ссылку) → выбираешь функцию → при желании пишешь уточнение → ИИ делает результат: билеты, конспект, ответ на вопрос или вопросы-карточки.

**Принципы:**
1. **ИИ пишет только содержание.** Нумерация билетов, подписи тем, проверка вариантов ответа, проверка цитат, хранение, интерфейс — код.
2. **Только по материалу.** «Ответ на вопрос» строится только по файлам; если ответа нет, так и написано. Цитаты показываются, только если код нашёл их в тексте.
3. **Исходные файлы не хранятся** — только извлечённый текст и результаты. Удаление результата стирает и текст.
4. **ИИ сменный:** провайдер, модель и ключ меняются в Настройках, без кода. Ключи хранятся зашифрованными и на экран не возвращаются.
5. **Деньги видны:** каждый вызов ИИ и распознавания записывается; внизу Настроек — токены и примерная сумма за месяц из бюджета 500 ₽.
6. **Ошибки не молчат:** любая ошибка — понятное сообщение + «Повторить».
7. **Как приложение:** PWA, иконка на экране «Домой», оболочка открывается из кэша мгновенно. Звуков нет.

## 2. Экраны и путь пользователя

Навигация: стрелка ‹ слева сверху открывает меню страниц.

1. **Привет** — простое приветствие (первая страница меню).
2. **Главная** — пиксельные портреты философов; под каждым имя на родном языке и по-русски. Тап → мини-биография и второй пиксельный портрет (философа или его труда). Данные — `static/philosophers.json`.
3. **Создать** — три окошка: (а) материал: файлы/фото, вставка текста, ссылка, «откуда и докуда» (необязательно); (б) функция; (в) «уточни, что нужно» (для «Ответа на вопрос» это поле — сам вопрос). Дальше — экран создания с анимацией и статусами.
4. **История** — все результаты: открыть или удалить (удаляется и результат, и извлечённый текст).
5. **Настройки** — вопросы (число, сложность, таймер, подсказки), палитра, ИИ (провайдер, модель, ключ, «Проверить связь»), пароль, внизу расходы.

## 3. Функции (`app/work/pipeline.py`)

| Функция | Что делает ИИ | Что делает код |
|---|---|---|
| **Все возможные билеты** (`make_tickets`) | делит материал на темы, составляет билеты по всем темам, в билете 2–3 вопроса | убирает дубли, нумерует билеты, подписывает тему у каждого вопроса, проверяет, что ни одна тема не осталась без вопросов (если осталась — один дополнительный запрос) |
| **Конспект** (`make_summary`) | разделы: тема, заголовок, главное пунктами, термины | склеивает части большого материала, подписывает темы |
| **Ответ на вопрос** (`make_answer`) | отвечает только по материалу, `found=false`, если ответа нет | если материал не влезает в запрос — выбирает самые подходящие куски; оставляет только цитаты, которые правда есть в тексте; при «нет ответа» пишет «В загруженных файлах ответа на этот вопрос нет.» |
| **Создать вопросы** (`make_questions`) | вопросы трёх видов: один из 4, несколько верных, верно/неверно; объяснение, подсказка, цитата | смесь видов по уровню, проверка (4 варианта и один верный и т. п.), неудачные — одним запросом на замену, перемешивание вариантов, подсказка без ответа |

**Темы.** Одна тема — всё по ней, подписи у элементов не показываются. Несколько тем (обычно несколько файлов) — каждый билет/вопрос/раздел подписан темой (по имени файла или по теме, которую определил ИИ). Код склеивает одинаковые темы («Электролиз» и «электролиз.»).

**Большой материал.** Текст режется на куски по заголовкам/слайдам/страницам (`split_text`), чтобы каждый запрос влезал в модель (у YandexGPT запрос + ответ ≤ 32 000 токенов). Больше `MAX_TEXT_CHARS` (≈ 220 страниц) за раз не берём — человек видит понятный текст: сколько страниц и что сделать.

**Карточки** (страница прохождения): по одной, прогресс, мягкая зелёная/красная подсветка после ответа, таймер и подсказки — по Настройкам. В конце — итог и все вопросы списком карточек; тап по карточке → объяснение.

## 4. Технологии

| Часть | Что | Почему |
|---|---|---|
| Сервер | Python 3.12 + FastAPI + Uvicorn | как в KvizY |
| Интерфейс | один HTML + CSS + JS, без сборки | нечего ломать, правится с iPad |
| PWA | `manifest.json` + `sw.js` | иконка на «Домой», мгновенный запуск |
| Текст из файлов | pypdf, python-docx, python-pptx, BeautifulSoup | надёжно, легко |
| Фото и сканы | Yandex Vision OCR (запасной путь — Claude) | YandexGPT картинки не читает |
| База | SQLAlchemy: SQLite локально, YDB Serverless в облаке | как в KvizY |
| Хостинг | Yandex Cloud Serverless Containers (контейнер `bilety`) | открывается в России без VPN |
| Деплой | GitHub Actions `.github/workflows/bilety.yml` | пуш в `main` с изменениями в `bilety/` = обновление |

## 5. Структура

```
bilety/
  app/
    main.py          запуск, /api/health, отдача интерфейса, миграции при старте
    config.py        переменные окружения + «ручки»: функции, уровни, лимиты
    db.py            таблицы и подключение
    migrations.py    свои миграции (как добавить поле — в шапке файла)
    auth.py          вход по паролю (хэш), cookie на год, пауза после 5 ошибок
    crypto.py        шифрование ключей ИИ (KEY_SECRET)
    store.py         настройки в базе: провайдер, ключи, палитра, вопросы, бюджет
    ai/              адаптеры YandexGPT, GigaChat, Claude, OpenAI-совместимый, пробный
    work/
      material.py    текст из файлов/фото/ссылок, чистка, «откуда докуда», деление на куски, проверка цитат
      ocr.py         распознавание фото и сканов
      prompts.py     тексты запросов к ИИ
      pipeline.py    четыре функции + статус задачи
      mockai.py      пробный ИИ для тестов и показа без ключа
    api/routes.py    все адреса API
  static/
    index.html app.css app.js   интерфейс
    pixel.js         пиксельные портреты (рисуются кодом)
    philosophers.json  список философов и тексты (заполняет владелец)
    sw.js manifest.json icons/
  tests/             автотесты (pytest)
  scripts/           make_icons.py, hash_password.py, check_contrast.py
  docs/              этот файл, yandex_cloud.md, proverka.md
```

## 6. Данные (таблицы)

| Таблица | Что хранит |
|---|---|
| users | владелец: хэш пароля (если меняли в приложении), версия сессии |
| settings | «ключ → JSON»: `ai.provider`, `ai.<провайдер>.model/folder_id`, `key.<провайдер>.api_key` (зашифрован), `palette`, `quiz`, `price.<провайдер>`, `budget` |
| results | результат: `func`, `title`, `note` (уточнение / вопрос), `params`, `sources` (только имена), `topics`, `content` (JSON результата), `status`, `warnings`, `last_attempt` |
| result_texts | извлечённый текст частями по 200 000 символов |
| usage | каждый вызов ИИ и распознавания: модель, цель, токены, ₽ |
| upload_parts | временные куски файлов (удаляются сразу после чтения) |
| login_failures | ошибки входа (для паузы) |

## 7. Что где поменять (шпаргалка)

| Хочу… | Где |
|---|---|
| названия и описания функций | `app/config.py` → `FUNCTIONS` |
| уровни сложности вопросов: таймер, смесь видов, стиль | `app/config.py` → `LEVELS` |
| сколько вопросов в билете | `app/config.py` → `TICKET_QUESTIONS` |
| число файлов, размер, предел текста | `app/config.py` → `MAX_FILES`, `MAX_FILE_MB`, `MAX_TEXT_CHARS` |
| как ИИ пишет билеты / конспект / ответ / вопросы | `app/work/prompts.py` |
| общие правила для ИИ | `SYSTEM_RULES` в `app/ai/__init__.py` |
| список моделей в Настройках | `app/store.py` → `PROVIDERS` |
| цены ИИ по умолчанию | `PRICES` в `app/ai/yandex.py` (или в Настройках приложения) |
| цену распознавания фото | `app/config.py` → `OCR_PRICE_RUB` |
| философов, биографии, портреты | `static/philosophers.json` (формат — в начале `static/pixel.js`) |
| палитры | `static/app.css` (раздел 1) + `PALETTES` в `app/store.py` + `PALETTE_NAMES`/`PALETTE_BG` в `static/app.js` + цвета в `<script>` в `static/index.html` |
| тексты на экранах | `static/app.js` (функции `page…`) |
| анимацию загрузки | `static/app.css` → «Загрузка» и `loaderHTML()` в `static/app.js` |
| новое поле в таблице | `app/db.py` + миграция в `app/migrations.py` |

## 8. Тесты

```
cd bilety
pip install -r requirements-dev.txt
python -m pytest -q tests
```
Тесты идут в GitHub Actions перед каждым деплоем BiletY и ещё раз внутри собранного образа.
